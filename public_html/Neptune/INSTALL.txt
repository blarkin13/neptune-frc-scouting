Neptune - Public 1.0 Self-Hosted Installation Guide
=====================================================

Neptune is a PHP/MySQL application. It does NOT use Python requirements.txt and
does NOT require /Neptune/admin/install.php.

FRESH INSTALLATION
------------------

1. Requirements

   - PHP 8.x
   - PDO MySQL
   - cURL
   - PHP sessions
   - MySQL 8.x or compatible MariaDB
   - Apache/Nginx or another PHP-capable web server
   - HTTPS for production
   - The Blue Alliance API key
   - GD or Imagick recommended for pit-photo optimization

2. Directory layout

   public_html/Neptune/     Public web application
   neptune_secure/          Private PHP configuration/helpers; keep outside web root
   sql/                     Baseline database schema
   scripts/                 Host/support scripts

3. Database

   Create an EMPTY database and import:

     sql/neptune_schema.sql

   This is the Public 1.0 baseline schema and includes the Platform Owner MFA
   schema used by clean installations.

4. Private configuration

   Copy:

     neptune_secure/config.example.php

   to:

     neptune_secure/config.php

   Enter database settings, base URL/timezone, TBA API key, and application
   settings. Never commit live credentials.

   Important application settings:

     platform_organization_id = 1

       The first organization created on a clean database normally receives
       ID 1 and becomes the installation's platform organization.

     allow_public_registration = false

       The FIRST organization may always be created.
       false = additional organizations cannot self-register.
       true  = this installation may accept additional organization signups.

     platform_owner_auth = strong

       strong = Google sign-in OR password + TOTP authenticator/recovery code.
       google = Google sign-in only.

       Historical "auto" and "password" values are treated as "strong"; they do
       not downgrade Platform Owner access to password-only.

     mfa_encryption_key

       A stable dedicated key is recommended for encrypting TOTP seeds at rest.
       It can be configured here or through NEPTUNE_MFA_ENCRYPTION_KEY.

       Example generator:

         php -r 'echo base64_encode(random_bytes(32)), PHP_EOL;'

5. First-run organization setup

   Open:

     /Neptune/register.php

   On an empty database the page becomes "Set Up Neptune".

   Create:

   - Organization / school / club name
   - Optional FRC team number
   - Platform Owner display name
   - Platform Owner username
   - Platform Owner email
   - Password (minimum 10 characters)

   Neptune creates:

   - the first organization
   - a unique organization sign-in slug
   - the first Owner account
   - the FRC team and primary-team assignment when a team number was supplied

   On a normal clean database this first organization receives ID 1 and is the
   platform organization.

   If allow_public_registration is false, later public organization creation is
   disabled even though first-run setup remains available on an empty database.

6. Sign in

   Password sign-in uses:

     organization name or slug + username + password

   A Gmail account and Google Workspace are NOT required for a private
   self-hosted Neptune installation.

7. Platform Owner strong authentication

   Platform Owners require strong authentication for high-value tools including:

   - File Manager
   - Maintenance Console
   - Platform Administration
   - AUGUR/platform operations

   Supported sign-in paths:

     Google sign-in
       OR
     Neptune password + TOTP authenticator code

   On the first successful Platform Owner password login, Neptune starts
   Google Authenticator enrollment.

   Neptune displays:

   - a QR code
   - a manual setup-key fallback
   - one-time recovery codes after successful enrollment

   Save recovery codes outside the Neptune server.

8. Optional Google OAuth / Workspace integration

   Google OAuth is optional.

   Supported environment variables include:

     GOOGLE_OAUTH_CLIENT_ID="..."
     GOOGLE_OAUTH_CLIENT_SECRET="..."
     GOOGLE_OAUTH_REDIRECT_URI="https://your-host/Neptune/auth/google-callback.php"

   Existing users can link through exact verified-email matching.

   Organizations may optionally configure approved Workspace-domain
   auto-provisioning for Scout accounts.

9. Create the rest of the team

   Sign in as the first Owner, then open:

     Command Center -> Organization -> Teams & Users

   Role ceiling:

   - Strategy manages Scout and may assign up to Strategy
   - Admin manages Scout/Strategy and may assign up to Admin
   - Owner manages lower roles and may assign up to Owner
   - users cannot change their own role or status

   Admin+ can also add/edit organization FRC teams.

10. Validate the installation

   Check:

   - Scouting hub
   - Analytics & Strategy hub
   - Command Center
   - System Check
   - Teams & Users
   - Platform Administration
   - File Manager
   - Maintenance Console
   - Platform Owner MFA
   - Match Scouting action record/undo
   - TBA/event sync if a TBA key is configured

MULTI-ORGANIZATION HOSTING
--------------------------

For an installation intended to host multiple organizations:

1. Set allow_public_registration=true only if organizations may self-register.
2. Leave it false if the platform owner will onboard organizations manually.
3. Each organization receives its own Owner/Admin/Strategy/Scout accounts.
4. Only Owners in platform_organization_id receive installation-wide platform
   administration tools.
5. Tenant-owned operational data remains organization-scoped.
6. Offline sync credentials must be organization-bound.

SELF-HOST SECURITY
------------------

- Keep neptune_secure outside the public web root.
- Never commit config.php or live OAuth/TBA/database/MFA secrets.
- Keep HTTPS enabled in production.
- Keep uploads non-executable.
- Keep deployment ZIPs, .bak*, .before*, SQL dumps, logs, env files, and hidden
  files out of the public web root.
- Platform Owner tools require strong authentication.
- Use a dedicated stable MFA encryption key.
- Keep recovery codes outside the Neptune server.

UPDATES AND DATABASE MIGRATIONS
-------------------------------

Neptune uses self-contained application migrations recorded in:

  neptune_migrations

Maintenance Console shows installed update history and database migration
history.

File rollback does NOT automatically reverse database migrations.

PRODUCTION BACKUPS
------------------

The hosted Neptune deployment can use encrypted GitHub-based production
backups. See:

  public_html/Neptune/docs/PRODUCTION_BACKUP_AND_RESTORE.md

for backup and restore procedures.

CI / SOURCE VALIDATION
----------------------

The repository includes:

  .github/workflows/php-lint.yml

GitHub Actions runs PHP syntax validation across all PHP files on pushes and
pull requests to main.

PRODUCTION HANDOFF
------------------

The platform owner should know how to:

- manage organizations in Platform Administration
- recover organization owners
- suspend/reactivate tenants
- export organization data
- manage users/roles/teams/invitations
- manage organization themes
- manage files through File Manager
- install/rollback Maintenance Console packages
- review neptune_migrations
- manage Platform Owner MFA/recovery codes
- review production backup status and restore documentation
